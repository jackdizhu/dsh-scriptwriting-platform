# 包名调整：`dsh-scriptwriting-store-local` → `dsh-scriptwriting-store`

- 状态：accepted（2026-11-21 用户拍板）
- 日期：2026-11-21
- 关联功能：全平台（包标识，不含业务实现）
- 关联决策：`docs/decisions/2026-11-21-项目代码目录大纲.md`（包粒度）、`docs/decisions/2026-11-21-存储后端与store-local定位.md`（职责变更）

## 背景

存储决策（`docs/decisions/2026-11-21-存储后端与store-local定位.md:32`）把 `store-local` 从「自研 SQLite Provider」降级为「领域 spec 声明」，真正的 Provider 是 harness 的 `@deepseek-ai/dsh-storage-sqlite`。于是包名 `dsh-scriptwriting-store-local` 的两个词都失真：

- `store`：它不存储任何数据，只声明 `defineDomain` 的 schema；
- `local`：后端由 harness 提供，且可替换（sqlite / json / 远程），本包不感知。

`rules/plugin-package.md:31` 要求包名按当前稳定职责命名，因此需要改名。评审记录见 `docs/reviews/2026-11-21-架构评审-骨架阶段.md` §3.1。

## 选项与取舍

| 选项 | 优点 | 代价 |
|---|---|---|
| A. 保持 `dsh-scriptwriting-store-local` 不变 | 零改动，引用点不动 | 包名持续暗示「本地存储实现」，后来者会来这里找数据库代码 |
| B. 改 `dsh-scriptwriting-domains` | 精确表达「多个领域 spec」 | 与「存储」语义脱离，需重建心智；`domains` 与后续可能的领域插件包命名易混 |
| **C. 改 `dsh-scriptwriting-store`（已选）** | 去掉失真的 `-local`，保留 `store` 与「领域存储 spec」的关联；改动面最小 | 目录名仍是 `store-local`，与包名不完全一致 |
| D. 改 `dsh-scriptwriting-platform` | — | **不可行**：与组合包 `dsh-scriptwriting-platform` 同 workspace 重名，`pnpm install` 会报重复包名 |

> 方案 D 曾被执行到一半（并连带把组合包改名为 `-bundle`），随后按用户指令撤销，回到方案 C。

## 结论

1. `packages/store-local` 的 npm 包名改为 **`dsh-scriptwriting-store`**；
2. **目录名保持 `packages/store-local`**，不随包名调整（改名只动标识，不动路径，避免文档与工具链大面积改动）；
3. 组合包维持 **`dsh-scriptwriting-platform`**，`cordis.patch.yml` 的 `name` 字段不变；
4. 角色描述修正不属于本次改名范围，仍按评审 §3.1 另行列出的 3 处文档处理。

## 验证方式

- `grep -rn "dsh-scriptwriting-store-local\|dsh-scriptwriting-bundle" --include="*.json" --include="*.yml" --include="*.ts" --include="*.md" .`（排除 `.git`、`node_modules`、目录联接）应只剩历史决策记录与评审记录中的历史引用；
- `node -e "console.log(require('./packages/store-local/package.json').name)"` 输出 `dsh-scriptwriting-store`；
