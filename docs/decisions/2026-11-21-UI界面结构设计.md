## 设计方向（技能「五问」）

| 问 | 答案 |
|---|---|
| 用途 | 多个作品的管理与内容跳转，重复工作流是「切作品 → 看内容 → 返回列表」 |
| 受众 | 剧本创作者；先扫作品名、当前作品名与三视图入口 |
| 调性 | dense / quiet / scannable 的工具型界面，不作落地页式表达 |
| 记忆点 | 详情页 tabs 与右栏三 tab 的固定映射，用单一 accent 的选中态表达，不用装饰卡 |
| 约束 | React 18 注入式 `require('react')`、无 CSS 管线、lazy-CJS 产物、D1 β 承载、右栏 tab kind 固定 |

## 设计原则（来自「前端工程」子技能）

- `frontend-design-direction`：第一屏就是可用工作流；沿用仓库现有样式约定，不引入新依赖与新视觉系统。
- `react-patterns` / `frontend-patterns`：render 是 props+state 的纯函数；派生值在 render 中算，不放 `useEffect`；组合优先于继承；状态按作用域就近放置。
- `design-system`：先审计再定令牌，只保留被实际使用的token；避免「AI 凑数」式渐变、玻璃卡、无意义动效。
- `frontend-a11y`：语义 HTML 优先，ARIA 仅在原生语义不足时使用；键盘可达与焦点恢复是验收项。
- `click-path-audit`：逐触点追踪状态写入与副作用，防止「按钮存在但终态错误」；本决策 §点击路径审计为实施前必查表。

## 信息架构与路由（沿用用户拍板，不改 slot）

```
route = { page: 'works' }
      | { page: 'detail', workId: WorkId, tab: 'content' | 'overview' }
```

左栏入口 → 主列「我的作品」→ 作品详情 tabs【内容视图、作品概览】→ 内容视图里的三视图仍打开右栏既有三个 tab kind。`index.ts`、`PANEL_ID`、右栏注册、`WorkbenchService` 一律不动。

## 状态归属（react-patterns 决策树）

| 状态 | 归属 | 依据 |
|---|---|---|
| `route`（page / workId / tab） | `PlatformApp` 的 `useState` | 单树内低频共享，不写 service、不写 layout |
| 作品列表 / 当前作品 / view 快照 | 外部 store，经 `useWorkbench()` = `useSyncExternalStore` | 并发渲染下外部状态的安全接法；组件只读 |
| 搜索词、编辑态、确认弹窗、pending | 各自组件 `useState` | 只被一个组件使用，就近放置 |
| 选中作品 id（权威） | `WorkbenchService` / `activeWorkId` | D5：浏览器不写权威状态 |

不引入 Context+Reducer 或全局 store：当前只有 Tabs 一处需要跨层共享，用复合组件自带 Context 即可。

## 组件模式

- **Tabs 复合组件**：`Tabs` 提供 Context，`Tabs.List` / `Tabs.Trigger` / `Tabs.Panel` 组合；选中态由 `route.tab` 受控，不各自保存状态。
- **Card 组合**：`Card` + `CardHeader` + `CardBody` + `CardFooter`，用 `children` 拼装，不做「卡片套卡片」；作品卡是唯一列表项包装。
- **ViewState**：统一渲染 loading / error / empty / ready 四态，避免每个页面各写一套；服务不可用降级为空态而非崩溃。
- **FormField**：`label htmlFor` + `aria-describedby` + `role="alert"`，用于新建与重命名输入框。

## 点击路径审计（实施前必查，来自 click-path-audit）

状态副作用图：

```
STORE: route（useState）
  openWork(id)   → sets {page:'detail', workId:id, tab:'content'}；RESETS 无
  backToWorks()  → sets {page:'works'}；不写 layout / sidebarRight
  setTab(tab)    → sets {tab}；不写 service
STORE: WorkbenchSnapshot（外部，只读）
  view / activeWork / works 由 service 命令后通知更新；组件不写
```

| 触点 | 调用序列 | 期望终态 | 风险与防护 |
|---|---|---|---|
| 左栏「创作平台」 | 壳层 `selectPanel` → 我们的 effect `openTab(lastKind)` | 主列显示作品列表、右栏展开到上次视图 | `selectPanel` 幂等、重复点击不关闭右栏是 D1 已知代价；effect 只监听 panel 切换，内部路由变化不触发 |
| 作品卡「打开」 | `openWork(id)` → 若非当前作品则 `await switchWork(id)` | 详情显示该作品，右栏数据随之更新 | 异步完成前 `view` 仍是旧作品：详情用 `activeWork.id === route.workId` 校验，不一致显示 loading，不渲染错配数据 |
| 详情页 tabs | `setTab(tab)` | 仅主列切换内容面板 | 不写 service、不改右栏；右栏由内容视图的 chips 显式驱动 |
| 三视图 chips | `openView(kind)` → 右栏展开对应 tab | 右栏显示所选视图 | 不做 toggle，避免与 D1「重复点击不关闭」冲突 |
| 新建 / 重命名 | `await createWork/renameWork` → 快照通知 | 列表与详情标题更新 | 按钮 pending 禁用；不拿命令返回值直接塞列表，只以快照渲染 |
| 软删 | `await deleteWork(id)` → service 切 active → 快照通知 | 作品从列表消失；若删的是当前作品，详情回退列表 | 在 `PlatformApp` 派生校验 `route.workId ∈ works`，不存在即 `backToWorks()`，防止停在已删作品 |
| 返回列表 | `backToWorks()` | 列表页；焦点回到对应作品卡 | 不主动关闭右栏（D1 代价）；焦点回退由 `useEffect` + `ref` 完成 |

## 无障碍与响应式（WCAG 2.2 AA 清单）

- 所有操作用 `<button>` / `<a>`，禁止无 role 的 `div onClick`；图标按钮给 `aria-label`。
- tabs：`role="tablist"`、`role="tab"`、`aria-selected`、`aria-controls`，支持左右方向键与 Enter/Space。
- 表单：`label htmlFor` + `aria-describedby` + `aria-invalid` + `role="alert"`；不用 placeholder 代替 label。
- 确认弹窗：`role="dialog"`、`aria-modal="true"`、打开时移入焦点、关闭时回到触发按钮、Escape 取消。
- 状态变化用 `aria-live="polite"` 播报；`prefers-reduced-motion` 下关闭过渡。
- 卡片网格用 `auto-fit / minmax` 自适应，控件尺寸稳定；长标题换行不溢出。
