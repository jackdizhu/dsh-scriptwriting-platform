# 静态数据来源：内置 mock fixture（D3-A）

- 状态：accepted（2026-11-21 用户拍板）
- 日期：2026-11-21
- 关联功能：阶段 1 UI 静态部分（`docs/plans/2026-11-21-implementation-steps.md` §2.3、§3.7）
- 关联决策：`docs/decisions/2026-11-21-UI入口与承载位置.md`（D1）、`docs/decisions/2026-11-21-客户端构建链.md`（D2）

## 背景

阶段 1 的三块静态视图（世界地图 / 人物关系 / 时间线）需要有数据才能渲染。排期原则是「UI 静态部分先落地、不依赖存储与模型」（`AGENT.md` §9、架构文档 §2.4），因此数据源必须在阶段 2（core 类型）/ 阶段 3（store spec）之前独立可用。

## 选项与取舍

| 选项 | 说明 | 优点 | 代价 |
|---|---|---|---|
| **A. 内置 mock fixture（已选）** | `src/client/mock/*.ts` 导出假数据，字段与未来领域类型同形，文件头标注 `TODO(阶段 5)` | UI 可独立先行；字段同形使阶段 5 替换零返工 | 阶段 5 前数据是假的，需在文件头显式标注避免误用 |
| B. 直接读 core 类型 | 先完成阶段 2 领域类型 | 数据契约统一 | 把 UI 拖到阶段 2 之后，违背「UI 先行」排期 |
| C. 从示例剧本文件读取 | 引入文件读取与解析 | 数据真实 | 超出静态范围，引入文件 IO 与解析复杂度 |

## 结论

采用 **A**，并遵守实施文档 §2.3 的约定：

1. mock 数据集中在 `src/client/mock/`（`world.ts` / `characters.ts` / `events.ts`），与视图组件、图表纯函数分离；
2. 每个 mock 文件头写明「阶段 5 由 `dsh-scriptwriting-core` 同名类型替换，字段保持一致以免返工」的 TODO 标记；
3. 数据字段与架构文档 §4.4 的领域划分（地点 / 人物 / 关系 / 事件）保持同形，但不能 import `dsh-scriptwriting-core`（阶段 1 边界：`docs/plans/2026-11-21-implementation-steps.md` §3.1 明确不 import core/store/tools）；
4. 阶段 5 替换的判据：`grep -r "mock/" packages/ui/src` 无命中，且面板数据来自领域存储、刷新不丢。
