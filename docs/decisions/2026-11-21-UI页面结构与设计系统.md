## 背景

阶段 1.5 已把单页工作台做完整（`entries/PlatformPage.tsx:63-149` 同时承载作品列表、三视图入口与统计摘要），但它仍是**一页聚合**：没有「我的作品」独立页，也没有作品详情的 tabs，信息层级与操作语境混在一起。`index.ts:20,22-26,65-73` 只注册一个 `main` key 与三个固定右栏 tab kind，这一结构由 D1 的 β 决定，不可为多页面轻易改动。

用户要求按前端项目的常规架构重做 UI 结构：入口「我的作品」→ 作品详情 tabs【内容视图、作品概览】；标准优先，先出详细设计，确认后再执行。

## 选项与取舍

| 方案 | 结构 | 优点 | 代价 |
|---|---|---|---|
| α 维持单页聚合 | 一个 `PlatformPage` 继续加区块 | 零注册改动 | 信息层级不清，作品管理与视图入口互相挤压；不达用户目标 |
| **β 多页 + tabs（已选）** | 主列内部分页：我的作品 → 作品详情 tabs；三视图仍走右栏 | 符合常规工作台结构；不动 D1 slot 注册；保留 β 已知代价的现状 | 需引入 UI-local 路由与组件分层 |
| γ 三视图改主列内嵌 | 详情内再做一层子 tab，不再用右栏 | 三视图与作品详情同屏 | 与 D1 冲突，要改 right-tab 注册与文档，回归面大 |

β 的关键前提：主列只有一个 `main` key，因此「多个页面」是**同一 key 内的 UI 状态切换**，不是新增 slot 或新增 `MainPanelId`。

## 结论

1. **信息架构**：左栏「创作平台」入口（不变）→ 主列「我的作品」列表 → 选中作品进入「作品详情」→ tabs【内容视图、作品概览】→ 内容视图里的三视图继续打开右栏既有三个 tab。
2. **技术分层**：`app`（壳/路由/tabs 容器）→ `features`（作品、视图）→ `shared/ui`（设计系统组件）→ `services`（现有 `WorkbenchService`）。
3. **设计系统**：`shared/tokens.ts` + 内联样式 + shell 的 CSS 变量；单一 accent `#3370ff`；不引入 CSS 管线、不引外部字体。
4. **数据流**：UI-local `route` 只管页面与 tab；领域数据只读 `useWorkbench()` 快照；所有写操作走 `getService().<命令>()`；不做乐观更新。
5. **承载不变**：`index.ts` 的 slot 注册、`PANEL_ID`、右栏三个 tab kind、D5 单向同步与软删语义均不改。

## 详细规格

### 路由与页面

```
route = { page: 'works' }
      | { page: 'detail', workId: WorkId, tab: 'content' | 'overview' }
```

| 页面/tab | 内容 | 关键交互 |
|---|---|---|
| 我的作品 | 标题 + 新建、搜索/排序、作品卡片网格、空态/错误态 | 打开作品、重命名、软删（二次确认） |
| 作品概览 | 地点/路线/人物/关系/事件统计卡、创建/更新时间、危险区 | 重命名、删除、跳内容视图 |
| 内容视图 | 三视图切换 chips + 复用现有 `PanelShell`/`ChartCanvas` + 右栏联动提示 | 打开右栏对应 tab；切换作品时数据随之变 |

`route` 存在 `app/` 的 UI-local state（初始实现用 `useState`，必要时再提为 Context）；它不写入 `WorkbenchService`，阶段 5 替换 service 后路由行为不变。切换作品后详情跟随 `activeWork`，tab 保留。

### 目录与职责

```
src/client/
  app/           PlatformApp.tsx（挂载 + 面包屑）、route.ts（类型与切换函数）
  features/
    works/       WorksPage.tsx / WorkCard.tsx / WorkDetail.tsx / OverviewTab.tsx / ContentViewTab.tsx
    views/       WorldMap.tsx / Relations.tsx / Timeline.tsx（由 panels/ 迁入，逻辑不变）
  shared/
    ui/          Button / Tabs / Card / StatGrid / PageHeader / Breadcrumb / EmptyState / ConfirmDialog
    tokens.ts    设计令牌（唯一样式常量出口）
    hooks/       纯 UI hook（如 useConfirmDialog）
  charts/        保留原位：三个 option 纯函数，不参与页面结构
  contract.ts / store.ts / useWorkbench.ts / service/mock.ts
                保留原位：逻辑上归服务层，物理不迁移，保证阶段 5 替换点仍是一行
  entries/PlatformPage.tsx  变薄为只挂载 PlatformApp（保留 PropsRuntime 注入）
  index.ts      不变
```

### 设计令牌（`shared/tokens.ts`）

| 类别 | 值 | 说明 |
|---|---|---|
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 | 8pt 网格；组件内 8/12，区块间 16/24 |
| 圆角 | 6 / 8 / 12 | 与现有 `styles.ts` 的 6 对齐，大卡片用 12 |
| 字号 | 20 / 14 / 13 / 12 | 标题/区标题/正文/辅助，最多四层 |
| 主色 | `#3370ff` | 沿用 `theme.ts` 与 `s.buttonPrimary`，不换色板 |
| 表面/边框/文字 | 读 shell CSS 变量 | 深浅主题跟随宿主，不硬编码背景 |
| 动效 | 150–200ms，`transform`/`opacity` | hover/active/focus；`prefers-reduced-motion` 时关闭 |

**有意偏离技能默认值**：不采用 44px 触控下限（这是桌面 Web 面板，不是移动端）；不采用推荐色板（与宿主视觉一致优先于个性化）；不引入外部字体与 CSS 文件（构建链约束，见 D2）。每个组件需覆盖默认 / hover / active / focus / disabled / loading；危险操作用确认弹窗而非红色强调块。

### 可访问性与响应式

- tabs 用 `role="tablist"` / `tab` / `tabpanel` + `aria-selected`，支持左右方向键与 Enter/Space。
- 删除、重命名等破坏性操作给确认弹窗，Escape 取消，焦点回到触发按钮。
- 主列变窄时卡片网格降为单列、统计卡自动换行；每个页面只有一个主视觉焦点。
- 服务暂不可用时显示空态或错误态，不崩溃（对齐阶段 5 的降级要求）。

### 不变与边界

- 不改 `index.ts` 的 slot 注册、`PANEL_ID`、右栏三个 tab kind；重复点击左栏不关闭右栏仍是 D1 已知代价。
- 组件不 import `service/mock.ts`、不直接写 `WorkbenchSnapshot`；软删与单活跃域语义由 service 保证。
- 不 import `core`/`store`/`tools`；不引入持久化、路由库、CSS 管线或新依赖。

- 静态：`pnpm typecheck`、`pnpm build` 通过；产物仍满足 lazy-CJS 契约（`process.env` = 0、无 ESM 残留、`__ModuleLoader__.load` = 1、NOTICE = 1）。
